import numpy as np

from config import A_INIT, b_E, BASE_RELEASE_RATE


def run_releaser(V, D_fast, HabituationSignal):
    raw_emotion_impact = A_INIT @ V + b_E * D_fast
    release_rate = float(np.clip(BASE_RELEASE_RATE * (1 + HabituationSignal), 0.0, 0.9))

2. slow_path.py 中 V 的完整计算部分

完整原文（含上下文）：

import numpy as np

from config import w_s, u_s, W_v, U_v, v_s, v_v, b_v, b_s, ETA, W_H


def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))


def run_slow_path(x, ReframedContext, M, B, w_PFC, HabituationSignal):
    z_s = (
        w_s @ (x + ReframedContext)
        + u_s @ M
        + v_s @ B
        + ETA * w_PFC
        + W_H * HabituationSignal
        + b_s
    )
    D_slow = float(sigmoid(z_s))

    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
    V = sigmoid(z_v)
    return D_slow, V

V 的关键行：
    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
    V = sigmoid(z_v)

z_v 是 2 维向量（W_v 是 2x8 矩阵），V = sigmoid(z_v) 也是 2 维。

4. 任务 4 的六个逐条回答

问题 1：V 是几维的？V[0]、V[1] 分别代表什么？

V 是 2 维的。

代码里没有注释说明 V[0]/V[1] 的语义。从公式与下游使用反推：
- z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
- W_v 是 2x8 矩阵，所以 z_v 是 2 维，V = sigmoid(z_v) 也是 2 维
- V 进入 emotion_releaser：raw_emotion_impact = A_INIT @ V + b_E * D_fast
- A_INIT 是 4x2 矩阵，A_INIT @ V 是 4 维
- 从 A_INIT 第一行 [-0.5, 0.5] 和 config 注释"V[0]=惩罚→负效价, V[1]=奖励→正效价"可推：
  V[0] = 惩罚/危险信号（值越大，越倾向惩罚）
  V[1] = 奖励/正面信号（值越大，越倾向奖励）
- 但这条注释在 A_INIT 行内，是 A_INIT 的设计意图，不是 V 的官方定义

问题 2：D_fast 是标量还是向量？几维？

D_fast 是标量（0 维）。

从 fast_path.py 与 emotion_releaser.py 的使用看：
- emotion_releaser: raw_emotion_impact = A_INIT @ V + b_E * D_fast
- b_E 是 4 维向量，b_E * D_fast 是逐元素乘，结果 4 维
- 所以 D_fast 必须是标量（否则广播会出错）
- 在 fast_path 中 D_fast 由 sigmoid(z_fast) 算出，z_fast 是标量

问题 3：released_impact 是几维的？它怎么从 V 和 D_fast 算出来的？贴出完整公式。

released_impact 是 4 维。

完整公式链：
(1) raw_emotion_impact = A_INIT @ V + b_E * D_fast
    - A_INIT: 4x2 矩阵
    - V: 2 维
    - A_INIT @ V: 4 维
    - b_E: 4 维
    - D_fast: 标量
    - b_E * D_fast: 4 维（逐元素）
    - raw_emotion_impact: 4 维

(2) release_rate = clip(BASE_RELEASE_RATE * (1 + HabituationSignal), 0.0, 0.9)
    - release_rate: 标量

(3) released_impact = raw_emotion_impact * (1 - release_rate)
    - raw_emotion_impact: 4 维
    - (1 - release_rate): 标量
    - released_impact: 4 维

问题 4：released_impact 有没有可能产生正值？如果有，在什么条件下？

有，但第 0 维很难。

逐维分析 released_impact = (A_INIT @ V + b_E * D_fast) * (1 - release_rate)：

第 0 维：
  A_INIT[0] = [-0.5, 0.5]
  b_E[0] = -1.0
  raw_emotion_impact[0] = -0.5*V[0] + 0.5*V[1] - 1.0*D_fast
  released_impact[0] = raw_emotion_impact[0] * (1 - release_rate)

  V[0]、V[1] 都在 [0,1]（sigmoid 输出），D_fast 在 [0,1]
  -0.5*V[0] 范围 [-0.5, 0]
  +0.5*V[1] 范围 [0, 0.5]
  -1.0*D_fast 范围 [-1, 0]
  合计范围 [-1.5, 0.5]
  乘以 (1-release_rate)（范围 [0.1, 0.7]）
  released_impact[0] 范围 [-1.05, 0.35]

  正值条件：0.5*V[1] > 0.5*V[0] + 1.0*D_fast
  即 V[1] > V[0] + 2*D_fast
  在 M1 三场景中：
  - 被骂：D_fast=0.794，需要 V[1] > V[0] + 1.588，几乎不可能（V 都在[0,1]）
  - 被夸：D_fast=0.450，需要 V[1] > V[0] + 0.900，也很难
  - 所以第 0 维在三场景下都是负值（被骂 -0.3025、被夸 -0.4439）

第 1~3 维：
  A_INIT[1] = [0.2, -0.2]，b_E[1] = 0.3
  raw_emotion_impact[1] = 0.2*V[0] - 0.2*V[1] + 0.3*D_fast
  范围 [-0.2, 0.5]，released_impact[1] 范围 [-0.14, 0.35]
  正值条件较容易满足（V[0] 大、D_fast 大时为正）

  实测三场景 released_impact[1]：被夸 0.105、被骂 0.105、被质疑 0.112（都为正）

结论：released_impact 第 0 维在三场景下都是负值（被 b_E[0]=-1.0 压住），第 1~3 维可能为正。

问题 5：E_raw 的 4 个维度里，除了第 0 维，其他三维有明确语义吗？代码里有没有说明？

没有明确语义说明。

代码中没有任何注释说明 E_raw 各维度的语义。从公式反推：
- E_raw = clip(LAMBDA*E_prev + released_impact + C_INIT@(B-B_INIT), -1, 1)
- 第 0 维：从 A_INIT[0]=[-0.5,0.5] 和 b_E[0]=-1.0 可推是"效价/正负"维度
- 第 1~3 维：A_INIT[1~3] 和 b_E[1~3] 都是较小正数，没有命名
- 猜测可能是"唤醒度/紧张度/期待"等子维度，但代码未注明

问题 6：从 V 到 E_raw[0]，整条链路上，哪一个环节最可能"把正值压成了负值"？列出候选。

按链路顺序列出候选环节：

环节 A：V = sigmoid(z_v)
  - z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
  - b_v = [0.5, 0.5]，所以 z_v 基线偏高
  - V[0] 和 V[1] 都在 [0,1]，且因为 b_v=0.5，基线都在 0.5+ 附近
  - 这一步本身不会把正值压成负值（sigmoid 输出恒正）

环节 B：raw_emotion_impact[0] = A_INIT[0] @ V + b_E[0] * D_fast
  - A_INIT[0] = [-0.5, 0.5]
  - b_E[0] = -1.0（B_E_DANGER_VALENCE）
  - 这是最大的嫌疑点：b_E[0] = -1.0 把整个第 0 维往下压
  - 当 D_fast 较大时（被骂 D_fast=0.794），b_E[0]*D_fast = -0.794，已经把正值压成负值
  - 即使 V[1] 高（奖励信号强），0.5*V[1] 最多 +0.5，抵不过 -1.0*D_fast

环节 C：released_impact = raw_emotion_impact * (1 - release_rate)
  - (1 - release_rate) 恒为正（[0.1, 0.7]），不改变符号
  - 不是嫌疑点

环节 D：E_raw = clip(LAMBDA*E_prev + released_impact + C_INIT@(B-B_INIT), -1, 1)
  - LAMBDA*E_prev：首轮 E_prev=0，后续轮才有效
  - C_INIT@(B-B_INIT)：B 初始 [0.5,0.5,0.5,0.5]，B_INIT 同值，所以首轮此项=0
  - 首轮 E_raw[0] ≈ released_impact[0]，所以问题在环节 B

主要嫌疑：环节 B（b_E[0] = -1.0 即 B_E_DANGER_VALENCE）
  - b_E[0] = -1.0 设计意图是"危险关键词驱动的负效价偏置"
  - 但 b_E[0] * D_fast 这一项，D_fast 是快通路危险检测，无论被骂还是被夸，D_fast 都不为 0（被夸也有 0.45）
  - 这导致第 0 维始终被往下压

次要嫌疑：环节 A 的 b_v = [0.5, 0.5]
  - 让 V[0] 和 V[1] 基线都偏高（0.62+），但 A_INIT[0]=[-0.5,0.5] 让 V[0] 贡献负、V[1] 贡献正
  - 若 V[0] 和 V[1] 接近，正负抵消，b_E[0]*D_fast 主导结果
