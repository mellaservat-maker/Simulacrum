   NVIDIA GeForce RTX 5060 Laptop GPU with CUDA capability sm_120 is not
   compatible with the current PyTorch installation.
   The current PyTorch install supports CUDA capabilities
   sm_50 sm_60 sm_61 sm_70 sm_75 sm_80 sm_86 sm_90.

5. torch 官方给出的修复建议（实测原文）：
   当前 torch==2.14.1+cu126 不含该 GPU 的内核，需按对应 CUDA 版本重装，例如：
   cu130 / cu132 / cu134 三种构建。

6. 结论：现有 torch 是 CPU 可用、GPU 不可用。若本阶段不处理，embedder 只能跑 CPU。

六、需要裁决的问题（三选一 + 选型）
============================================================

问题一：嵌入环境放在哪里？

选项 A：在 D 盘新建独立 venv（例如 d:\aiqg\venv）
  优点：依赖、模型、缓存全部落在 D 盘，C 盘零新增，最符合“都放 D 盘”。
  代价：今后运行项目需改用该 venv 的 python；会改变现有运行方式（可提供启动脚本缓解）。
  成本：需重新下载 torch（cu130 版，约 3~5 GB）到 D 盘。

选项 B：在现有 TRAE python 环境里原地重装 GPU 版 torch
  优点：运行方式完全不变，改动最小，最省事。
  代价：约 3~5 GB 会落在 C 盘；且会改动现有全局环境，存在影响其他依赖的小风险。

选项 C：先不修 GPU，embedder 先用 CPU 跑
  优点：不下载大包，最快能跑通，零风险。
  代价：BGE-Large 在 CPU 上较慢（每条约几十到上百毫秒）；GPU 通路未验证，遗留问题。

问题二：可插拔 embedder 的默认语义后端用哪个模型？

选项 1：BGE-Large-zh-v1.5
  维度 1024，中文效果最好，模型约 1.3 GB。与之前既定方案一致。
选项 2：bge-base-zh-v1.5
  维度 768，模型约 400 MB，速度与效果折中。
选项 3：bge-small-zh-v1.5
  维度 512，模型约 100 MB，最快最省空间，效果略弱。

说明：维度选择会直接决定后续 config.py / state.py 的改法，请一并裁定。

问题三：本阶段“可插拔 embedder”的接口边界如何界定？
