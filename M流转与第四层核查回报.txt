import numpy as np

from config import w_s, u_s, W_v, U_v, v_s, v_v, b_v, b_s, ETA, W_H


def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))


def run_slow_path(x, ReframedContext, M, B, w_PFC, HabituationSignal):
    z_s = (
        w_s @ (x + ReframedContext)
        + u_s @ M
        + v_s @ B
        + ETA * w_PFC
        + W_H * HabituationSignal
        + b_s
    )
    D_slow = float(sigmoid(z_s))

    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
    V = sigmoid(z_v)
    return D_slow, V

一段话总结 M 的流转：
M 在 hippocampal_evaluator 里产生（TopK 候选 event_embedding 的归一化均值），
通过 HippocampalOutput 字典的 "M" 键返回给 pipeline.py；pipeline.py 取出后传给 slow_path.run_slow_path，
slow_path 用 M 做两件事——D_slow 计算里 u_s @ M（慢速危险度的记忆贡献项）、
V 计算里 U_v @ M（奖励/惩罚评估的记忆贡献项），也就是说 D_slow 和 V 共用同一个 M，
只在海马体里算一次，两处都用。M 没有传到其他模块（拦截层/策略层/情绪模块都不用 M）。
M_text 则从海马体经 pipeline 传到 state_translator 做提示词拼接，最终进 LLM。

4.2 slow_path 内部用 M 做了什么？贴出用到 M 的那几行。

用了两处，都在 slow_path.py 里：

第 18 行（z_s 的一部分，用于 D_slow 慢速危险判断）：
        + u_s @ M

第 26 行（z_v 的一部分，用于 V 奖励/惩罚评估）：
    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v


4.3 奖励/惩罚评估（V）在哪算？是 slow_path 内部算的，还是别处算的？

slow_path 内部算的。slow_path.py 第 26~27 行：

    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v
    V = sigmoid(z_v)

然后作为返回值的第二个元素返回给 pipeline（第 28 行 return D_slow, V）。
pipeline 里 V 只在第 91 行传给 emotion_releaser：
    raw_emotion_impact, released_impact, release_rate = run_releaser(V, D_fast, HabituationSignal)
没有别的地方再算 V。


4.4 V 的计算有没有用到 M？用到了 / 没用，给证据。

用到了。证据是 slow_path.py 第 26 行：

    z_v = W_v @ (x + ReframedContext) + U_v @ M + v_v * D_slow + b_v

其中 U_v @ M 就是 M 对 V（奖励/惩罚评估）的贡献项。
而且因为 D_slow 和 V 在同一个 run_slow_path 函数里、用的是同一个 M 参数，
所以确实是"只调一次 M，两处共用"，复用成立。
