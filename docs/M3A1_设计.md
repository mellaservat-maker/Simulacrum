## 第 1 节：现状

### 1.1 released_impact[0] 完整公式

```
raw_emotion_impact[0] = A_INIT[0] @ V + b_E[0] * D_fast
                     = -0.5 * V[0] + 0.5 * V[1] + (-1.0) * D_fast

released_impact[0] = raw_emotion_impact[0] * (1 - release_rate)
                   = (-0.5*V[0] + 0.5*V[1] - 1.0*D_fast) * (1 - release_rate)
```

其中：
- A_INIT[0] = [-0.5, 0.5]
- b_E[0] = B_E_DANGER_VALENCE = -1.0
- V[0]、V[1] ∈ [0, 1]（sigmoid 输出）
- D_fast ∈ [0, 1]
- release_rate ∈ [0, 0.9]，所以 (1 - release_rate) ∈ [0.1, 1.0]

### 1.2 实测三场景 D_fast 值

| 场景 | D_fast | V[0] | V[1] | released_impact[0] |
|------|--------|------|------|--------------------|
| 被骂 | 0.7941 | 0.731 | 0.672 | -0.3025 |
| 被夸 | 0.4502 | 0.624 | 0.721 | -0.4439 |
| 被质疑 | 0.5622 | 0.662 | 0.648 | -0.3636 |

### 1.3 b_E[0]、A_INIT[0] 当前值

- b_E[0] = -1.0（B_E_DANGER_VALENCE）
- A_INIT[0] = [-0.5, 0.5]

## 第 2 节：病根

### 一句话

被夸 E[0] 为负，是因为 b_E[0] = -1.0 把 D_fast（0.45）直接放大成 -0.45 的负向偏置，而 V[1] 的正向贡献（0.5*0.721 ≈ +0.36）抵不过它。

### 主要嫌疑项与数值证据

| 嫌疑项 | 数值证据 |
|--------|----------|
| b_E[0] = -1.0 | 被夸 D_fast=0.45，b_E[0]*D_fast = -0.45；被骂 D_fast=0.79，b_E[0]*D_fast = -0.79。无论被骂还是被夸，这一项都是负值 |
| A_INIT[0] = [-0.5, 0.5] | V[0] 与 V[1] 在三场景都接近（差 0.05~0.1），所以 -0.5*V[0]+0.5*V[1] 接近 0，无法压过 b_E[0]*D_fast |
| V[0] 与 V[1] 区分度低 | 被骂 V=[0.731,0.672]、被夸 V=[0.624,0.721]、被质疑 V=[0.662,0.648]。被夸 V[1]>V[0] 只多 0.097，0.5*0.097=+0.049，远不够抵消 -0.45 |

根因：**b_E[0] 与 D_fast 的乘积是非线性的"危险门控"，但 D_fast 在被夸场景也高（0.45），把"非危险"也压成了负值。**

## 第 3 节：三个候选方案

### 方案 A：让 b_E[0] 随奖励信号浮动

```
b_E[0] = -1.0 + k * V[1]
```

- 当 V[1] 高（有奖励信号）时，b_E[0] 从 -1.0 向 0 或正方向浮动
- k 取 1.0（结构性依据：让 V[1]=1 时 b_E[0]=0，完全消除危险偏置；V[1]=0 时 b_E[0]=-1.0，保持原行为）
- 不取 k=2.0 这种"为了让被夸为正而硬凑"的值
- k=1.0 的语义：奖励信号强度等于 1 时，关闭危险偏置

修改后：
```
raw_emotion_impact[0] = -0.5*V[0] + 0.5*V[1] + (-1.0 + 1.0*V[1]) * D_fast
                     = -0.5*V[0] + 0.5*V[1] - D_fast + V[1]*D_fast
```

### 方案 B：给 E[0] 单独加一条正向注入

不动 b_E[0]，在 emotion_releaser 或 emotion.py 中另加：

```
raw_emotion_impact[0] += alpha * V[1]
```

- alpha 取 1.0（结构性依据：让奖励信号对 E[0] 的贡献与 A_INIT[0] 的 0.5 系数同量级，但不再乘 0.5）
- 加在 emotion_releaser 的 raw_emotion_impact 计算后、release_rate 乘之前

修改后：
```
raw_emotion_impact[0] = -0.5*V[0] + 0.5*V[1] - 1.0*D_fast + 1.0*V[1]
                     = -0.5*V[0] + 1.5*V[1] - 1.0*D_fast
```

### 方案 C：D_fast 对 E[0] 的影响进行场景区分

让 D_fast 只在真正负面场景下压 E[0]：

```
# 用 V[0] 与 V[1] 的差值判断"真正负面"
danger_gate = max(0, V[0] - V[1])  # V[0] > V[1] 才算负面
raw_emotion_impact[0] = -0.5*V[0] + 0.5*V[1] + b_E[0] * danger_gate
```

- 不需要新系数
- 语义：只有当惩罚信号 V[0] 大于奖励信号 V[1] 时，D_fast 才作为危险偏置生效
- 被夸 V[1]>V[0]，danger_gate=0，b_E[0]*0=0，不再压 E[0]
- 被骂 V[0]>V[1]，danger_gate = V[0]-V[1]，b_E[0] 仍生效（但乘的是差值而非 D_fast）

修改后：
```
raw_emotion_impact[0] = -0.5*V[0] + 0.5*V[1] - 1.0 * max(0, V[0]-V[1])
```

## 第 5 节：推荐方案

**推荐方案 C。**

理由：
1. 唯一同时满足三个锚点（被夸>0、被骂<0、被质疑<0、三场景两两不同）
2. 不引入任何新参数（k、alpha 都不需要），纯结构性改动
3. 改动最小（只改 emotion_releaser.py 一行）
4. 语义最清晰：用 V 内部的"惩罚 vs 奖励"信号差做场景区分，符合 M3"让信号本身决定走向"
5. 不破坏 b_E[0] = -1.0 的设计意图（仍生效，但只在真正负面场景下生效）
