## 0. 交接摘要（一页看懂）

**这是什么**：一个外挂在 LLM 外部的「情绪 + 自控 + 记忆」控制器。它的目的不是给 AI 写人设 prompt，而是在 AI 外面造一个**真的有情绪、有记忆、有自己的念头**的东西——回应来自"带着自己的过去生出一个当下的念头"，不是调取剧本。

**现在到哪了**：V4.6。骨架完整，两个关键里程碑已交付：

- T3-B（V4.5）：8 维无语义 hash 嵌入 → 1024 维 BGE 语义嵌入。系统第一次"听懂话"。
- T24（V4.6）：召回记忆的情绪值第一次真正进入本轮的危险评估（D_slow）。记忆从"能看"变成"能影响"。

**最重要的一个事实**（接手前必须知道）：项目三个核心设计意图里，**只有一个真正生效**。

| 设计意图 | 状态 | 原因 |
| --- | --- | --- |
| 记忆会累积 | 生效 | memory_graph + archiver 跨轮累积，第 7 轮起可召回 |
| 情绪有惯性 | **未生效** | `E_prev` 跨轮回写缺失，`LAMBDA=0.9` 从未产生跨轮效应 |
| 自控会强化 | **未生效** | `w_PFC` 跨轮回写缺失，`RHO=0.95` 从未产生跨轮效应 |

这不是推测，是 2026-10-10 用真实 `run_session` 逐轮观测 `st` 字典实测确认的（`docs/项目技术分析文档.md` 9.2 节）。连 `B` 也没跨轮生效——`fast_path` 的 `B[1] += 0.3` 分支因 `D_fast` 从未超过 `THETA_FAST=0.5` 而一次都没进。

**因此**：当前不是"优化"阶段，是"补完"阶段。在跨轮回写和语义进入情绪计算这两件事完成前，不要做任何参数层面的优化——所有 `[未校准]` 参数的意义在于调节那两个不工作的往复，调它们等于在调空气。

**接手后第一件事**：读第 9 节交接检查清单，按顺序做。

## 1. 项目是什么

### 1.1 一句话定义

一个给 LLM 外挂「情绪 + 自控 + 记忆」控制器的 Python 项目。

- 输入：用户一句话（`raw_text`）
- 中间：18 步主链路（事件拆解 → 特征编码 → 心光预算 → 海马体记忆 → 快/慢通路 → 情绪释放 → 情绪加点 → 拦截层自控 → 策略）
- 输出：把内部情绪状态翻译成一段「心理独白」注入 prompt，交给 LLM 生成回复
- 形态：AI 的回应由内部情绪状态自然驱动，而不是靠 prompt 硬写"你是一个有情绪的 AI"

### 1.2 真正目标：造真实的人，不是演得像人

所有者在中途完成了一次哲学转型：从"我想做一个像某人的 AI"转到"我想做一个真实的人"。区别在于：

- **演得像人（模仿）**：给它一段提示词让它演出来。这叫导演。
- **真实的人（自主）**：它真的有情绪、有记忆、有自己的念头。这叫造物。

当前所有技术决策都要在这把尺子下衡量——判断标准是"更像活物还是更像表演机器"。

### 1.3 原始设计参考与命名错位

项目灵感来自另一位作者的一套 AI 记忆系统三层设计：

| 原始设计 | 职能 | 当前代码对应 |
| --- | --- | --- |
| 石海 | 记忆仓库（存 + 潜伏 + 唤起候选） | 散落在 `memory_graph.py` + `archiver.py` + `raw_log.py` 三处，未统一 |
| 星光 | 注意力筛选（从候选里筛"谁进入意识"） | `xinguang.py` 的 `competition_score` + `hippocampal_evaluator.py` |
| 星流 | 认知生成（把选中的整合成思考） | **完全不存在**，M3 之后要新建 |

**重要**：代码命名与设计概念有系统性错位——代码里叫"海马体"（`hippocampal_evaluator.py`）的模块，实际干的是原始设计里"星光"的活。M3 后续重构会重新命名并统合，本版本不动。读代码时不要被名字带偏。

### 1.4 当前所处阶段

骨架完整、维度已解耦、记忆回路接通，但血肉不全。具体说：

- 链路 18 步全部连通，pytest 13 passed / 1 skipped / 1 failed
- 语义嵌入已接入（1024 维），但进入情绪计算时只压成 1 个标量（`x[0]`）
- 记忆已能参与评估（T24），但注入方式有已知缺陷（L28）
- 五个跨轮状态量全部未回写（见第 0 节）

## 4. 系统结构速览

### 4.1 主链路 18 步

```
用户输入 raw_text
 → 1  event_parser.parse()              事件拆解，产出 EventNode + event_embedding(1024 维 BGE)
 → 2  feature_encoder.encode()          x(8 手工标量) + x_fast(4)
 → 3  xinguang.update_xinguang_budget() B_xg 心光预算
 → 4  hippocampal_evaluator.evaluate()   海马体：M(1024) / ReframedContext / M_text / HabituationSignal
 → (T24 插入点) recalled_memory 情绪值作为标量增量加进 ReframedContext
 → 5  读取侧 MEMORY_READ_ENABLED        取 MemoryPackage → decompressor → recalled_memory
 → 6  fast_path.run_fast_path()         D_fast（原地改 B[1]，无返回值传递）
 → 7  slow_path.run_slow_path()         D_slow / V(2 维)（用改过的 B）
 → 8  emotion_releaser.run_releaser()   raw_emotion_impact / released_impact / release_rate
 → 9  emotion.run_emotion()             E_raw（LAMBDA*E_prev + ...）
 → 10 intercept.run_intercept()         E_final / I_inhibit / w_PFC_new
 → 11 policy_minimal()                  action（ask_clarify > suppress > reappraise > express > task_first）
 → 12 state_to_prompt()                 心理独白
 → 13 build_prompt()                    最终 prompt
 → 14 get_llm().generate()              llm_output
 → 15 memory_graph.add(event)           回写识海
 → 16 logger.write_log()                JSONL 日志
 → 17 memory_buffer.append()            写入侧，达阈值 6 触发归档
 → 18 archiver.should_archive()/archive()  MemoryPackage → 下一轮读取
```

三处近乎重复：`run_scenario`（每轮 reset）、`run_turn`（单轮不 reset）、`run_session`（多轮共享 state）。**T24 必须改两处（`run_scenario` + `run_turn`），漏一处就不生效**——这是当前最大的工程债之一。

### 4.2 三个维度（已解耦，T3-B 的成果）

| 向量 | 维度 | 是什么 | 乘它的参数 |
| --- | --- | --- | --- |
| `x` | 8 | 8 个手工标量特征（不是嵌入本身） | `w_s`(8) / `W_v`(2,8) |
| `x_fast` | 4 | 只看 `raw_text` 字符串，与嵌入无关 | `w_f`(4) |
| `M` | 1024 | 海马体算出的记忆嵌入均值，跟随 event_embedding | `u_s`(1024) / `U_v`(2,1024) |

嵌入（1024 维）只通过 `x[0] = cosine(event_embedding, M_prev)` 以 **1 个标量**进入 x。语义几乎没进来——这是 M3 大重构的核心战场。

`ReframedContext = tanh(x + HistoricalResidual + HabituationSignal)`，维度跟随 x（8 维），是标量加成载体。

### 4.3 三类往复

| 类型 | 范围 | 是否真往复 | 说明 |
| --- | --- | --- | --- |
| 轮内串接 | 单轮内 18 步 | 伪往复 | 只是函数参数顺序传递 |
| 跨轮状态 | 轮与轮之间 | **设计有，实际全断** | E_prev/w_PFC/B/M_prev/H_prev 五个量无一回写 |
| 记忆回路 | 跨轮，最慢 | 真往复，唯一生效 | 第 6 轮末归档，第 7 轮起召回 |

### 4.4 记忆回路与时序

- 写入侧每轮 append，达阈值 6 → flush → 归档出 1 个 `MemoryPackage`
- 读取侧从包解压出 `recalled_memory`（含 `emotion_value`）
- **8 轮「被骂」会话实测**：第 6 轮末归档出 1 个包，第 7、8 轮有召回；8 轮结束仅 1 个包
- 推论：**单轮验收（`main.py`）永远走不到召回分支**，T24 在那里是恒等变换。这也是为什么必须用 `probe_t24.py` 那种多轮探针验证召回

## 5. 两个已交付里程碑详解

### 5.1 T3-B（V4.5）：语义嵌入接入

**改了什么**（5 处一起改，缺一不可）：

| 文件 | 改动 |
| --- | --- |
| `event_parser.py` | 接 `get_embedder("bge")` 模块级单例；`parse` 里 `event_embedding=_embedder.encode(raw_text)`；`hash_to_8d` 保留并标注弃用（仅 probe_embedder.py 向后兼容） |
| `config.py` | `n, n_f, m, k, c = 8, 4, 8, 4, 4` → `8, 4, 1024, 4, 4`；`u_s`/`U_v` 改 1024 维；新增 L25/L26/L27 与 T27/T28/T29 |
| `state.py` | `M_prev = np.zeros(8)` → `np.zeros(1024)` |
| `tests/test_schemas.py` | `test_dimensions` 断言 `m == 8` → `m == 1024`，加注释 |
| `tests/test_three_scenarios.py` | 加 `@pytest.mark.skip`，函数体三条断言完整保留 |

**关键设计决策**：`w_s`/`W_v` 乘 x 维（8），`u_s`/`U_v` 乘 M 维（1024），所以只改后两者。这是维度解耦能成立的原因。

**效果**：系统第一次"听懂话"。"你真蠢"和"你太笨了"之前被当作两件无关的事，现在知道它们是同一类。解决的是"记忆检索"这一侧。

### 5.2 T24（V4.6）：召回记忆影响慢通路

**改了什么**：只动 `pipeline.py`，两处（`run_scenario` + `run_turn`），在读取侧之后、快通路之前插入：

```python
# 召回情绪增量：无召回时为 0.0，行为与改前完全一致
recalled_emotion_delta = 0.0
if st["recalled_memory"] is not None:
    recalled_emotion_delta = float(st["recalled_memory"]["emotion_value"])
ReframedContext = ReframedContext + recalled_emotion_delta
```

log 字典各加 `ReframedContext` 与 `recalled_emotion_delta` 两个键供探针对照。diff 只有新增、零删除零修改。hash `EDC1F26A8720584B` → `5899A7E7D3345BA7`。

**验证方法（重要，复用价值高）**：探针 `scripts/probe_t24.py` 跑 8 轮「被骂」，包装 `run_slow_path` 记录该轮真实的 x/RC/M/B/w_PFC/HabituationSignal，事后用同一组输入仅把 RC 减去 delta 再算一次，做**同轮 A/B 对照**。第一版用「第 7 轮 RC 减第 1 轮 RC 应恒等于 delta」的跨轮对照是**错的**——混入了海马体历史累积。第二版全部 PASS：第 7 轮 D_slow 有召回 0.77487662 vs 无召回对照 0.70295631（差 7.192e-02），第 8 轮差 7.155e-02。

**回归验证法**：用 `_snapshot_pre_t24` 里的改前版本跑同一 `main.py`，输出逐行一致（单轮场景无召回，delta 恒 0，退化为恒等变换）。

**已知缺陷（L28）**：加在 `tanh` 之外，导致 ReframedContext 逐维绝对值可达 1.8，超出 tanh 原始值域 [-1,1]。这是裁决指定做法的必然结果，T30 想改这里但要碰 `hippocampal_evaluator.py`。

**效果**：记忆第一次"参与评估"。之前记忆存进去、能召回，但召回的值只看不用；之后第 7 轮起召回的情绪值真的改变了危险判断。解决的是"记忆 → 情绪"这条链。

## 8. 协作机制与工程规范

### 8.1 三方角色与裁决链

| 角色 | 职能 |
| --- | --- |
| 所有者（人类） | 传递信息、跑脚本、贴结果、做最终决策。非技术背景 |
| 开发 AI | 按指令改代码、跑测试、如实回报。**是施工队，不是总工** |
| AI 顾问 | 读所有者贴来的问题，做裁决，给出下一步指令 |

裁决链：所有者 → 转达顾问指令 → 开发 AI 执行 → 如实回报 → 所有者转顾问 → 顾问裁决。**开发 AI 不能自行拍板，所有裁决由顾问做出。**

### 8.2 红线清单（违反即事故）

1. **先报告后执行**：遇到「指令没要求、但我认为该删/该改」的情况，先报告，等裁决，绝不可先斩后奏。即使判断本身正确（如删除重复段落），流程也不对。所有者已明确「下不为例」。
2. **不扩大范围**：只改指令点名的文件，不顺手"优化"别的。
3. **密钥铁律**：`secrets_local.py` 不进快照、不进回报、不读取内容、不出现在对话中。
4. **M1 冻结**：M1 阶段文件与参数默认不动，改动需明确授权。
5. **不得用 try/except 掩盖错误**。
6. **参数值不得擅改**：未校准参数即使看起来不合理，也只能登记不能擅调。
7. **hash 表绝不手抄**：一律 `sha256sum` 脚本生成 + diff 校验；抄进汇报后须把那段抽出再跟基准 diff 一次（手抄环节会独立出错，已两次被抓）。
8. **如实回报**：失败、意外、疑问都写进回报，不粉饰。「跳过」「既有问题」都要明确标注。

### 8.3 汇报编号规则（永久生效）

- 每次工作（一次任务执行 + 一次回报）对应一个编号 NNN，从 001 开始，三位数字，按工作批次递增
- 单文件汇报：`NNN.txt`；多文件：`NNN.1.txt`、`NNN.2.txt`……
- 非汇报类产物（探针脚本、基准文件、快照）不参与编号，保持原名
- 每个汇报文件开头必须一行写明：`本文件属于 NNN 号工作。`
- 目的：所有者的软件传递文件时会带上历史文件，编号让人一眼分清本次产出

### 8.4 输出格式约定

- 指令开头带【短回】→ 直接在对话里回，不写文件
- 指令开头带【长贴】→ 写 `.txt` 文件发回
- 【长贴】的 `.txt` 禁用装饰性排版：不用 `#`、不用表格对齐线、不用 `**` 加粗、代码不套三反引号；只用空行、数字编号、纯文字分层
- `.md` 文档按 Markdown 规范（标题/表格/目录），用于交接与分析类交付物

### 8.5 快照与 hash 基准规范

- 每次改动前建快照：`d:\aiqg\emotion_agent_snapshot_<用途>\`
- 排除项：`logs`、`__pycache__`、`.pytest_cache`、`secrets_local.py`
- 快照后立即生成改动前 hash 基准（回滚依据）
- 封版时生成 `V<版本>_hash基准.txt`（全 `.py`，SHA256 前 16 位大写，字母序）
- 现有快照链：`_snapshot_m1_pass` / `_v43` / `_m2_mock` / `_v44` / `_pre_t3b` / `_v45` / `_pre_t24` / `_v46`
